## クラスとオブジェクトの関係

```rb
object = Class.new
program_quest = Game.new
```

この話をする上で欠かせないのがクラスとオブジェクトの関係です。
端的に言うと**クラスは設計図**で、オブジェクトは**クラスを元に作られた製品**です。

Ruby上では`Class名.new`をするとオブジェクトが生まれます。
もちろんオブジェクトは生み出しただけではデータとして保持してくれないため`object = クラス名.new`と変数に代入することでobject内にクラス名(Game等)のオブジェクトが保持されます。

※objectの中身はClass.newで作られたオブジェクトが入っているメモリの住所を入れているだけですが、実質的にデータが入っているという処理になります。

```rb
class Game # クラスを作る宣言
  def appearance # メソッドを作る宣言
    puts "スライムが現れた!!" # メソッドを実行した時の内容
  end
end

game = Game.new # オブジェクト(インスタンス)を生成
game.appearance # => スライムが現れた!!
```

この状態で例えると、gameというオブジェクトはGameクラスを元にして作られています。そのためgameはGameクラス内で書かれたメソッド(appearance)を使うことが出来ます。

## クラスって何？

### クラスの基本

```rb
class Game
  # 本来はここにオブジェクトが生成される度にIDが+1される処理が入る
  # （説明のため省略）
  
  def appearance
    puts "スライム#{@id}が現れた!!"
  end
end

game1 = Game.new() # オブジェクト(インスタンス)を生成
game2 = Game.new() # 変数名は違うが代入するものは一緒
game1.appearance # => スライム1が現れた!!
game2.appearance # => スライム2が現れた!!
```

クラスは設計図です。
クラスはオブジェクトは生み出すことが出来る上複数作ることができます。

ただしそのオブジェクトは**全て同じものではなくそれぞれが独立**しています。

もしオブジェクト同士が同じだとするなら、スライム1に攻撃してもスライム2も同時に同じダメージを受けることになります。これだと変ですね。

ですから基本的にオブジェクト同士は同じクラスに属しますが別の個体という話になります。

### クラスは親子関係

```rb
# 親クラス
class Enemy
  def appearance
    puts "敵が現れた!!"
  end

  def attack
    puts "敵の攻撃!!"
  end
end

# 子クラス
class Slime < Enemy  # < でEnemyクラスを指定
  def appearance # 親クラスのappearanceメソッドを上書き（オーバーライド）している
    puts "スライムが現れた!!"
  end

  # attackメソッドは書かなくても親クラスから引き継がれる
end

class Dragon < Enemy
  def appearance
    puts "ドラゴンが現れた!!"
  end

  def breath # ドラゴンだけ新たにメソッドを追加する
    puts "炎を吐いた!!"
  end
end

slime = Slime.new
dragon = Dragon.new

slime.appearance  # => スライムが現れた!!
slime.attack      # => 敵の攻撃!! (Enemyからの引き継ぎ)

dragon.appearance # => ドラゴンが現れた!!
dragon.attack     # => 敵の攻撃!! (Enemyからの引き継ぎ)
dragon.breath     # => 炎を吐いた!!

slime.breath      # => エラー！Slimeにはbreathメソッドはない
```

クラスは大まかな設計図と具体的な設計図という親子関係を作ることが出来ます。

これが継承です。

`Slime < Enemy`の`<`がEnemyをSlimeに引き継ぐという親子関係を示します。親のクラスに書かれたものを子が引き継いでいるため、子のクラスからオブジェクトを作ったとしても、その子のオブジェクトは親クラスのメソッドを使えるという形になります。

## オブジェクトって何？

クラスの設計図から作られたモノそのものです。
ちなみに先程オブジェクト（インスタンス）と書きましたが以下の違いがあります。

| 用語 | 意味 |
| --- | --- |
| **オブジェクト** | Rubyに存在するすべてのもの |
| **インスタンス** | あるクラスから生成された具体的なオブジェクト |

クラスとの関係を強調する時に使っているというだけなのであまり気にしないでください。

ここまでの解説ではオブジェクトは今のところ2つのことが解説されています。

- `Class.new`から生まれること
- オブジェクト同士は独立したモノであること

さて、これで「Rubyで扱う全ての値はオブジェクト」を紐解くことができます。

### Rubyで扱う全ての値はオブジェクトである

```rb
# 全てのデータはオブジェクトであり、クラスは遡るとObjectクラスに繋がる
p 1.class # => Integer
p 1.is_a?(Object) # => true
p 1.class.ancestors # => [Integer, Numeric, Comparable, Object, Kernel, BasicObject]

p "hello".class # => String
p "hello".is_a?(Object) # => true
p "hello".class.ancestors # => [String, Comparable, Object, Kernel, BasicObject]
```

`object.class`は`object`のクラス名を返します。1の場合はIntegerという数字を扱います。

`object.is_a?(Object)`というのは少し説明が難しいですが、`object`のクラスを調べて、そのクラス自身が継承しているクラスのリストを遡って、指定した引数（`Object`)が無いかを探しに行きます。この場合はObjectがあったためtrueを返します。

最後に`.class.ancestors`でそのクラスの先祖をリストとして返します。すると`[Integer, Numeric, Comparable, Object, Kernel, BasicObject]`と長いですが途中に`Object`に行き着きます。

これは数値、文字列、配列、ハッシュ、nil、bool(true / false)全て**祖先をたどるとObjectに行き着きます。**

これが**「Rubyの全てのデータはオブジェクトである」**ということの本質になります。

:::message
Objectの祖先にKernelがありますがこのKernelはモジュールでObjectクラスがKernelをincludeしています。そのため**全てのオブジェクトでRubyの基本機能が呼び出せます。**`p`や`puts`なんかはその代表例です。
:::

## まとめ

- 数値も文字列も配列も全てObjectを祖先に持つオブジェクトである
- `1.class`や`"hi".class`のようにどんな値にもメソッドが呼べる
- Rubyの「全ての値がオブジェクト」の本質にあたる

これがRubyを書く上で「全ての値がオブジェクト」を意識することが大事と言われる理由です。
